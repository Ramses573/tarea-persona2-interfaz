Sección 2: Arquitectura, Componentes y Hooks en React Native

Entregable de Investigación Técnica – Persona 2 (25 %)

2.1. Arquitectura básica de una aplicación React Native

React Native es un framework de desarrollo móvil multiplataforma creado por Meta Platforms que permite construir aplicaciones nativas reales para Android e iOS utilizando JavaScript y la biblioteca React. A diferencia de los enfoques híbridos tradicionales basados en vistas web (WebViews), React Native traduce la jerarquía de componentes declarados en React directamente en controles nativos propios del sistema operativo anfitrión (Meta Platforms, 2025a).

2.1.1. Hilos principales de ejecución (Threads)

El entorno de ejecución de una aplicación React Native opera sobre tres hilos principales que trabajan de forma coordinada:

  1. Hilo de JavaScript (JS Thread): Es el hilo donde el motor de JavaScript (actualmente Hermes por defecto) ejecuta la lógica de negocio de la aplicación, procesa el árbol virtual de React, gestiona los estados (Hooks) y despacha las solicitudes de red.
  2. Hilo Principal o Nativo (Main / UI Thread): Es el hilo nativo del sistema operativo (Android o iOS) encargado de pintar la interfaz gráfica en la pantalla y capturar los eventos táctiles e interacciones del usuario.
  3. Hilo de Sombra (Shadow Thread): Hilo secundario que utiliza el motor de diseño multiplataforma Yoga (escrito en C++) para traducir las reglas de diseño Flexbox en coordenadas y dimensiones exactas antes de entregarlas al hilo nativo.

2.1.2. Evolución arquitectónica: Del Bridge a la Nueva Arquitectura (JSI)

En su diseño clásico, React Native comunicaba el hilo de JavaScript y el hilo Nativo mediante un puente asíncrono (Bridge) que serializaba mensajes en formato JSON. Para eliminar la sobrecarga de serialización en animaciones y listas extensas, las versiones modernas de React Native implementan la Nueva Arquitectura (Meta Platforms, 2025b), integrada por cuatro componentes clave:

  • JSI (JavaScript Interface): Capa en C++ que reemplaza al antiguo Bridge, permitiendo que JavaScript mantenga referencias directas a objetos nativos e invoque métodos de forma síncrona o asíncrona sin serializar cadenas JSON.
  • Fabric: Nuevo motor de renderizado de interfaz de usuario compartido en C++ que soporta renderizado concurrente y priorización de eventos urgentes.
  • TurboModules: Sistema de módulos nativos (cámara, sensores, red) que se cargan en memoria bajo demanda (lazy loading), optimizando el tiempo de inicio de la aplicación.
  • Codegen: Generador estático de código nativo que garantiza seguridad de tipos entre JavaScript y las capas nativas de Android e iOS.

2.2. Estructura y organización de componentes

En React Native, toda interfaz gráfica se modela mediante componentes funcionales: funciones de JavaScript independientes, reutilizables y declarativas que reciben propiedades inmutables de entrada (props), administran su propio estado local cuando es necesario y retornan elementos visuales descritos en sintaxis JSX (Boduch & Derks, 2020).

La interfaz se organiza como un árbol jerárquico con flujo de datos unidireccional (top-down):

  • Componente Raíz (App.js): Punto de entrada que inicializa la aplicación y monta la vista principal.
  • Componentes de Pantalla (src/screens/): Vistas completas como HomeScreen.js que gestionan el estado de los datos, los filtros y la estructura general de la pantalla.
  • Componentes Reutilizables (src/components/): Piezas modulares como ItemCard.js y CategoryFilter.js que reciben los datos de cada elemento mediante props y notifican acciones del usuario mediante funciones callback.
  • Capa de Datos y Estilos (src/data/ y src/styles/): Módulos dedicados a almacenar los datos de prueba (mock data), funciones normalizadoras y constantes globales de diseño.

2.3. Componentes principales: View, Text, FlatList, Image, ScrollView y StyleSheet

React Native proporciona un conjunto de componentes nucleares (Core Components) que se traducen en vistas nativas equivalentes en cada sistema operativo (Meta Platforms, 2025a):

  • View: Contenedor fundamental para construir la estructura visual (equivalente a android.view.View en Android y UIView en iOS). Utiliza diseño Flexbox con orientación vertical (flexDirection: 'column') por defecto.
  • Text: Único componente válido para mostrar cadenas de texto en pantalla (TextView / UITextView). Permite configurar tipografía, color y truncado de líneas mediante numberOfLines.
  • Image: Componente para renderizar recursos gráficos locales (require(...)) o remotos mediante URL (source={{ uri: 'https://...' }}). En imágenes remotas requiere definir explícitamente su ancho y alto en los estilos, y permite controlar el ajuste visual con resizeMode (cover, contain).
  • ScrollView: Contenedor desplazable que monta y renderiza todos sus elementos hijos simultáneamente en memoria. Resulta idóneo para vistas cortas o barras horizontales de categorías (horizontal={true}).
  • FlatList: Componente de alto rendimiento para mostrar listados dinámicos mediante virtualización (lazy rendering). Solo mantiene en memoria los elementos visibles en pantalla, recibiendo como propiedades esenciales data (arreglo de datos), renderItem (función que dibuja cada tarjeta) y keyExtractor (identificador único por registro).
  • StyleSheet: API de estilizado (StyleSheet.create({})) que define reglas visuales mediante objetos de JavaScript en notación camelCase y unidades independientes de la densidad de píxeles.
Criterio técnico ScrollView FlatList
Estrategia de renderizado Renderiza todos los elementos hijos de forma simultánea al montarse. Virtualización: renderiza únicamente los elementos visibles en la ventana actual.
Consumo de memoria Incrementa proporcionalmente al número total de elementos. Permanece estable incluso con cientos o miles de registros.
Caso de uso en la aplicación Barra horizontal de filtros por categoría (CategoryFilter.js). Listado principal de tarjetas de datos (HomeScreen.js).

2.4. Funcionamiento de useState y useEffect, con ejemplos

Los Hooks son funciones nativas de React que permiten gestionar el estado reactivo y el ciclo de vida dentro de componentes funcionales (Meta Platforms, 2025c).

2.4.1. Gestión de estado local con useState

El Hook useState declara una variable de estado que se preserva entre renderizados. Su invocación devuelve un par de elementos: el valor actual del estado y una función actualizadora que, al ser llamada, programa automáticamente el re-renderizado de la interfaz con los nuevos datos. 

import React, { useState } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';

export default function EjemploUseState() {
  // Declaración del estado local [valorActual, funcionActualizadora]
  const [favorito, setFavorito] = useState(false);

  return (
    <View style={styles.contenedor}>
      <Text style={styles.estado}>
        Estado del elemento: {favorito ? 'Guardado en Favoritos ♥' : 'Sin guardar ♡'}
      </Text>
      <TouchableOpacity
        style={styles.boton}
        onPress={() => setFavorito(!favorito)}
      >
        <Text style={styles.textoBoton}>Cambiar estado</Text>
      </TouchableOpacity>
    </View>
  );
}

const styles = StyleSheet.create({
  contenedor: { padding: 16, alignItems: 'center' },
  estado: { fontSize: 15, marginBottom: 10 },
  boton: { backgroundColor: '#2563EB', paddingVertical: 8, paddingHorizontal: 16, borderRadius: 8 },
  textoBoton: { color: '#FFFFFF', fontWeight: 'bold' },
});

2.4.2. Efectos secundarios y ciclo de vida con useEffect

El Hook useEffect permite ejecutar efectos secundarios después de que React Native ha renderizado el componente, tales como inicializar datos de prueba, realizar peticiones HTTP a una API REST o configurar temporizadores. Su ejecución se controla mediante su segundo parámetro (el arreglo de dependencias): un arreglo vacío [] indica que el efecto debe ejecutarse únicamente una vez al montar el componente en pantalla. 

import React, { useState, useEffect } from 'react';
import { View, Text, FlatList, ActivityIndicator } from 'react-native';
import { MOCK_ITEMS } from '../data/mockData';

export default function EjemploUseEffect() {
  const [items, setItems] = useState([]);
  const [cargando, setCargando] = useState(true);

  useEffect(() => {
    // Carga inicial de datos al montar el componente
    const timer = setTimeout(() => {
      setItems(MOCK_ITEMS);
      setCargando(false);
    }, 500);

    // Función de limpieza en caso de que el componente se desmonte
    return () => clearTimeout(timer);
  }, []); // Se ejecuta una sola vez al montar la vista

  if (cargando) {
    return <ActivityIndicator size="large" color="#2563EB" />;
  }

  return (
    <View style={{ flex: 1 }}>
      <FlatList
        data={items}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => <Text>{item.title}</Text>}
      />
    </View>
  );
}
